# M06: `lead`

## 1. Goal
`lead(k)` pairs every element with the element `k` positions later ("next value", "time until next event", look-ahead parsing). It is the mirror of `lag` (M05) and is delivered right after it so both share validation, docs wording and the README deviation entry.

## 2. Scope
**In:** `lead(offset, result_selector=..., *, default=None)` on `_LinqOps` (`FlpIt`, `FlpList`, `OrderedIt`, `Grouping`). Tuple result when no selector is given.
**Out:** zero/negative offsets (rejected, as in MoreLINQ); multi-offset look-ahead (use `window`, M02).

**MoreLINQ overload mapping**
| MoreLINQ | flpit |
|---|---|
| `Lead(offset, Func<T, T?, TResult>)` | `lead(offset, result_selector)` (lead value `None` past the end) |
| `Lead(offset, T defaultLeadValue, Func<T, T, TResult>)` | `lead(offset, result_selector, default=value)` |
| (none) | `lead(offset)` / `lead(offset, default=value)` → `(current, lead)` tuples |

## 3. Detailed design
### 3.1 Signatures
```python
@overload
def lead(self, offset: int) -> FlpIt[tuple[TItem, TItem | None]]: ...
@overload
def lead(self, offset: int, *, default: TDefault) -> FlpIt[tuple[TItem, TItem | TDefault]]: ...
@overload
def lead(self, offset: int, result_selector: Callable[[TItem, TItem | None], TResult]) -> FlpIt[TResult]: ...
@overload
def lead(
    self, offset: int, result_selector: Callable[[TItem, TItem | TDefault], TResult], *, default: TDefault
) -> FlpIt[TResult]: ...
```

### 3.2 Semantics
- Kind: intermediate, deferred. Buffering: partial (look-ahead of `offset` elements). Short-circuit: n/a.
- **Pull pattern (matches MoreLINQ):** before the first result, `offset + 1` source elements are pulled (or the whole source if shorter); afterwards one pull per result. The last `offset` results use `default` and pull nothing.
- Selector called as `result_selector(current, lead)`.
- Validation (eager): `offset` via `_require_index` + `_require_positive` (F05); `offset <= 0` → `ArgumentOutOfRangeError("offset")`; explicit `result_selector=None` → `ArgumentNoneError("result_selector")`.
- `offset >= len(source)`: every element pairs with `default`. Empty source → empty. `None` elements are ordinary values.
- Re-enumeration re-enumerates the source. A source exception raised while filling the look-ahead surfaces before any result is yielded (same as MoreLINQ, which prefetches identically).

### 3.3 Implementation sketch
```python
def lead(self, offset, result_selector=_SENTINEL, *, default=None):
    offset = _require_positive(_require_index(offset, "offset"), "offset")
    if result_selector is not _SENTINEL:
        _require_callable(result_selector, "result_selector")
    src = self._source()                                   # F05: FlpList → backing list
    def _generator():
        current, ahead = tee(src)
        leading = chain(islice(ahead, offset, None), repeat(default))
        if result_selector is _SENTINEL:
            return zip(current, leading)
        return map(result_selector, current, leading)
    return FlpIt(_FactoryIterable(_generator))
```
- `zip` pulls `current` first, so it stops as soon as the source is exhausted; the infinite `repeat(default)` is never over-consumed. O(n) time, O(min(offset, n)) memory (the `tee` buffer).
- `islice(ahead, offset, None)` on the first pull skips `offset` items, which `tee` buffers for `current`: this is exactly the `offset + 1` prefetch.
- **FlpList / `list` fast path** (`type(src) is list`): `zip(src, chain(islice(src, offset, None), repeat(default)))` without `tee`. Same values and callbacks; adopt only with a ≥ 15 % measured gain, as in M05. Note the pull pattern is unobservable on a list.

## 4. Tests
- **Ported:** none (D7). `LeadTest.cs` (10 cases) as checklist:
  - covered by own tests: laziness, negative/zero offset, explicit default, implicit default, offset > length, offset 1 and 2.
  - `NO_VALUE_TYPES`: implicit default `0` for ints → own test asserts `None`.
  - `NO_NULLABLE_DISTINCTION`: the two nullable-reference tests (compile-time only) → typing test.
  - Target: 100 % of applicable behaviours.
- **Own unit tests** (`tests/unit/morelinq/test_lead.py`):
  - `[1, 2, 3, 4].lead(1)` → `[(1, 2), (2, 3), (3, 4), (4, None)]`; `lead(2, f, default=0)`.
  - `offset ∈ {len-1, len, len+1, 2**31-1}`; `{0, -3}` raise at call time.
  - Pull counting: `take(1)` pulls `offset + 1` elements; `take(n)` pulls all n; nothing pulled before enumeration.
  - Source raising at position `offset` raises before the first result.
  - Selector argument order `(current, lead)`; `None` elements; one-shot vs list re-enumeration.
  - Round trip: `xs.lead(1).select(lambda t: t[0])` equals `xs`.
- **Contracts:** auto via registry (deferral, one-shot, no FlpList mutation, buffer bound = `offset`).
- **Typing** (`tests/typing/test_types_lead.py`): same four forms as M05.
