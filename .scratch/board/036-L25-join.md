# L25: `join`

## 1. Goal
Inner equi-join of two sequences by key, the operator behind C# `join ... on ... equals ...`. Python has no stdlib equivalent; users write nested loops (O(N·M)) or hand-roll a dict index. `rules.md` mandates an O(N + M) hash join. This card adds `join` with the classic result-selector form and the newer tuple-returning form, and lands the **join variant of the lookup builder** (`None` keys never match) reused by L26 and N04–N06.

## 2. Scope
**In:** `join(inner, outer_key_selector, inner_key_selector, result_selector=...)` on `_LinqOps`; `skip_none_keys=True` path of `_build_lookup` (flag defined in L20).
**Out:** comparer overloads (D3); left/right/full joins (N04–N06); `group_join` (L26).

## 3. Detailed design
### 3.1 Signatures
```python
TInner = TypeVar("TInner")

@overload
def join(self, inner: Iterable[TInner],
         outer_key_selector: Callable[[TItem], TKey],
         inner_key_selector: Callable[[TInner], TKey]) -> FlpIt[tuple[TItem, TInner]]: ...
@overload
def join(self, inner: Iterable[TInner],
         outer_key_selector: Callable[[TItem], TKey],
         inner_key_selector: Callable[[TInner], TKey],
         result_selector: Callable[[TItem, TInner], TResult]) -> FlpIt[TResult]: ...
```
`.NET` overload map: `Join(inner, outerKey, innerKey, resultSelector)` → 4-argument form; `Join(inner, outerKey, innerKey)` returning `IEnumerable<(TOuter Outer, TInner Inner)>` → 3-argument form returning plain `(outer, inner)` tuples (same choice as `zip`; no named fields); the two comparer overloads omitted (D3). **Note**: the tuple-returning overload is in `dotnet/runtime` `main` / .NET 11 previews (learn.microsoft.com lists it under `net-11.0` only), not in .NET 10 GA. Like `FullJoin` (README open question 2), it is verified by ported unit tests only until the harness oracle runs on an SDK that has it.

### 3.2 Semantics
- Kind: intermediate, deferred. Buffering: partial (`inner` fully buffered into a lookup; `self`/outer streamed). Short-circuit: stops pulling outer as soon as the consumer stops.
- Source-access order (as .NET's `JoinIterator`): on the first `next()`, pull the **first outer element**; if outer is empty, `inner` is never iterated and no key selector runs. Otherwise build the lookup from all of `inner` (calling `inner_key_selector` once per inner element), then, **if the lookup is empty, stop** without pulling more outer elements or calling `outer_key_selector`. Otherwise, for each outer element in order: compute its key and yield `result_selector(outer, inner)` for every matching inner element in inner order.
- Output order: outer order, then inner order within each outer element (documented .NET guarantee).
- **`None` keys never match (mirrors .NET)**: inner elements whose key is `None` are not stored; an outer element with key `None` matches nothing (`SkipsNullElements`, `SelectorsReturnNull`). Only `key is None` is excluded; composite keys such as `(None, 1)` match normally (like a C# anonymous type containing null). Documented in the docstring; not a deviation.
- Validation (eager): `inner is None` → `ArgumentNoneError("inner")`; `outer_key_selector`/`inner_key_selector`/explicit `result_selector=None` → `ArgumentNoneError(<name>)`.
- Keys use Python equality/hashing; an unhashable key raises `TypeError` (inner: during the build; outer: at that element).
- Re-enumeration re-reads both sources and rebuilds the lookup.

### 3.3 Implementation sketch
```python
def join(self, inner, outer_key_selector, inner_key_selector, result_selector=_SENTINEL):
    ...validation...
    pair = result_selector is _SENTINEL
    def _generator():
        it = iter(self)
        first = next(it, _MISSING)
        if first is _MISSING:
            return
        lookup = _build_lookup(inner, inner_key_selector, skip_none_keys=True)   # dict[key, Grouping]
        if not lookup:
            return
        get = lookup.get
        for outer in chain((first,), it):
            key = outer_key_selector(outer)
            group = None if key is None else get(key)
            if group:
                if pair:
                    for x in group: yield (outer, x)
                else:
                    for x in group: yield result_selector(outer, x)
    return FlpIt(_FactoryIterable(_generator))
```
- O(N + M + R) time (R = result size), O(M) memory: a hash join as required by `rules.md`.
- **FlpList fast path**: none (the inner lookup must be built regardless; outer is already streamed from the list).

## 4. Tests
- **Ported** `tests/nettests/test_join.py` from `JoinTests.cs` (31). `CustomerRec`/`OrderRec`/`AnagramRec`/`JoinRec` become frozen dataclasses.   - Expected skips: none. Target: 100 % ported.
- **Own unit tests** (`tests/unit/test_join.py`): empty outer never iterates `inner` (spy); empty lookup stops after one outer element and never calls `outer_key_selector`; inner fully read before the first result; `None` keys on either side never match while `(None, 1)` matches; duplicate keys produce the cross product in order; unhashable key `TypeError`; re-enumeration rebuilds; selector call counts.
- **Contracts**: auto via registry (deferral; one-shot outer and inner).
- **Typing**: `assert_type(flp.it([1]).join(["a"], lambda o: o, len), FlpIt[tuple[int, str]])`; with result selector `FlpIt[str]`.

- `native`: `idx = defaultdict(list)`; `for i in inner: idx[ik(i)].append(i)`; `[(o, i) for o in outer for i in idx.get(ok(o), ())]`
- `flpit-FlpIt` / `flpit-FlpList`: `.join(inner, ok, ik).to_list()` and with a result selector.
- Target ratio ≤ 1.3× (buffering).

## 11. Risks / open questions
- The card brief called the tuple overload ".NET 10"; the API docs show it only for .NET 11 (preview). Same treatment as `FullJoin` (board README open question 2) until GA.
- Plain tuples instead of named `(Outer, Inner)` fields: a `NamedTuple` would add attribute access but diverge from `zip`'s tuples; revisit together with N04–N06 if users ask.
