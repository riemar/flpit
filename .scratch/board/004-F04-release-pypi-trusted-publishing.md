# F04: Release: PyPI trusted publishing + attestations (uv)

## 1. Goal
Publishing a **GitHub Release** (tag `vX.Y.Z`) is the only way a version reaches PyPI (D10). The pipeline is uv-native (`uv version`, `uv build`, `uv publish`), uses **PyPI Trusted Publishing** (OIDC, no API tokens stored anywhere), and ships two kinds of provenance:
1. **PEP 740 attestations on PyPI**, generated by Astral's preview action [`astral-sh/attest-action`](https://github.com/astral-sh/attest-action) and uploaded automatically by `uv publish` (≥ 0.9.12 uploads `*.publish.attestation` files it finds next to the dists).
2. **GitHub artifact attestations** (SLSA build provenance) via `actions/attest-build-provenance`, verifiable with `gh attestation verify`.

Uploads are gated by a required reviewer on the `pypi` environment.

## 2. Scope
**In**
- `.github/workflows/release.yml`
- `ci.yml` gains `on: workflow_call` so the release re-runs the full gate on the tagged commit
- `CHANGELOG.md` (Keep a Changelog) with an `## [Unreleased]` section; release notes are taken from it
- Version policy: `pyproject.toml` on `main` carries the *next* dev version (e.g. `0.2.0.dev0`); the release job sets the real version from the tag without committing (`uv version --frozen`)
- One-time maintainer setup checklist (PyPI trusted publisher, GitHub environment, tag ruleset)

**Out:** TestPyPI (not chosen), automatic changelog generation, signing with GPG.

## 3. Detailed design
### 3.1 Trigger and guards
```yaml
name: Release
on:
  release:
    types: [published]
  workflow_dispatch:            # dry run: build + provenance, never publishes
    inputs:
      ref: { description: "tag to dry-run", required: true }
permissions: {}                 # every job declares its own minimum
```
- Tag format must match `^v(\d+\.\d+\.\d+)((a|b|rc)\d+)?(\.post\d+)?(\.dev\d+)?$` (PEP 440 subset); otherwise the `verify` job fails.
- A GitHub "pre-release" with an `rc`/`a`/`b` tag still publishes to PyPI (pip ignores pre-releases by default); `.dev` tags are rejected (dev builds are not published).

### 3.2 Jobs
```yaml
jobs:
  gate:                                    # full CI on the tagged commit
    uses: ./.github/workflows/ci.yml
    permissions: { contents: read }

  build:
    needs: gate
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write                      # sigstore for build provenance
      attestations: write                  # GitHub attestation store
    outputs: { version: ${{ steps.v.outputs.version }} }
    steps:
      - uses: actions/checkout@<sha>       # with: ref (dry-run input) / default tag ref
        with: { persist-credentials: false }
      - uses: astral-sh/setup-uv@<sha>     # v7; caching DISABLED in release jobs (cache-poisoning hardening)
        with: { enable-cache: false }
      - id: v
        run: |
          TAG="${GITHUB_REF_NAME:-${{ inputs.ref }}}"
          VERSION="${TAG#v}"
          [[ "$TAG" =~ ^v[0-9]+\.[0-9]+\.[0-9]+((a|b|rc)[0-9]+)?(\.post[0-9]+)?$ ]] || { echo "bad tag $TAG"; exit 1; }
          uv version "$VERSION" --frozen   # rewrites pyproject in the workspace only; no lock/sync
          echo "version=$VERSION" >> "$GITHUB_OUTPUT"
      - run: uv build --no-sources         # sdist + wheel, as an end user would build
      - run: |                             # built artefacts carry the tag version
          ls dist/flpit-${{ steps.v.outputs.version }}.tar.gz dist/flpit-${{ steps.v.outputs.version }}-py3-none-any.whl
          uv run --isolated --no-project --with dist/*.whl python -c \
            "import flpit,sys; assert flpit.__version__=='${{ steps.v.outputs.version }}', flpit.__version__"
      - run: uvx twine check --strict dist/*
      - uses: actions/attest-build-provenance@<sha>     # GitHub artifact attestation (SLSA provenance)
        with: { subject-path: "dist/*" }
      - uses: actions/upload-artifact@<sha>
        with: { name: dist, path: dist/, if-no-files-found: error }

  publish:
    if: github.event_name == 'release'
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: pypi                           # required reviewer + tag-only deployment rule
      url: https://pypi.org/project/flpit/${{ needs.build.outputs.version }}/
    permissions:
      id-token: write                      # Trusted Publishing + PEP 740 signing (same OIDC identity)
    steps:
      - uses: actions/download-artifact@<sha>
        with: { name: dist, path: dist/ }
      - uses: astral-sh/setup-uv@<sha>
        with: { enable-cache: false }
      # MUST be directly above `uv publish`, in the SAME job: the attestation identity
      # must equal the Trusted Publisher identity, and files created after upload are lost.
      - uses: astral-sh/attest-action@<sha>   # preview (v0.0.x): pin by SHA, review on each bump
        with: { paths: "dist/*" }
      - run: ls dist/*.publish.attestation    # fail fast if no attestation was produced
      - run: uv publish --trusted-publishing always dist/*
        # uv ≥ 0.9.12 auto-uploads matching *.publish.attestation files;
        # recent uv also revokes the short-lived PyPI token after publishing.

  verify-pypi:
    needs: [build, publish]
    runs-on: ubuntu-latest
    permissions: { contents: read }
    steps:
      - uses: astral-sh/setup-uv@<sha>
      - run: |                                # PyPI has the PEP 740 provenance for each file
          V=${{ needs.build.outputs.version }}
          for f in flpit-$V-py3-none-any.whl flpit-$V.tar.gz; do
            curl -fsS -H 'Accept: application/vnd.pypi.integrity.v1+json' \
              "https://pypi.org/integrity/flpit/$V/$f/provenance" | jq -e '.attestation_bundles | length > 0'
          done
      - run: |                                # clean install from PyPI works
          uv run --isolated --no-project --with "flpit==${{ needs.build.outputs.version }}" \
            python -c "from flpit import flp; print(flp.range(1,3).to_list())"

  release-assets:
    needs: [build, publish]
    runs-on: ubuntu-latest
    permissions: { contents: write }
    steps:
      - uses: actions/download-artifact@<sha>
        with: { name: dist, path: dist/ }
      - run: gh release upload "$GITHUB_REF_NAME" dist/* --repo "$GITHUB_REPOSITORY"
        env: { GH_TOKEN: "${{ github.token }}" }
```
### 3.3 Fallback if the preview action regresses
`astral-sh/attest-action` is explicitly early stage. If a SHA bump breaks it, replace that single step with the equivalent CLI (same identity, same output files):
```yaml
      - run: uvx --from pypi-attestations==<pinned> pypi-attestations sign dist/*
```
The rest of the job is unchanged. Both paths are documented in `RELEASING.md`.

### 3.4 One-time maintainer setup (`RELEASING.md`)
1. **PyPI** → project `flpit` → *Publishing* → add a GitHub Trusted Publisher: owner `andreacuneo`, repo `flp`, workflow `release.yml`, environment `pypi`. Remove any old API tokens used for 0.1.x uploads.
2. **GitHub** → Settings → Environments → `pypi`: required reviewer = maintainer; "Prevent self-review" off (single maintainer); deployment branches and tags: **tags matching `v*` only**.
3. **GitHub** → Rulesets → tags `v*`: restrict creation/deletion to maintainers; block force-updates.
4. **Releasing**: move `[Unreleased]` notes in CHANGELOG to `[X.Y.Z] - date`, merge, create the GitHub Release with tag `vX.Y.Z` on `main` → approve the `pypi` deployment → done. Then bump `pyproject` to the next `.dev0`.

## 4. Tests
- **Dry run** (`workflow_dispatch` with an existing tag, e.g. a throwaway `v0.2.0rc0` on a branch): `gate` + `build` succeed; the `dist` artifact contains both files; `gh attestation verify` succeeds; `publish` is skipped.
- **Negative**: dispatch with tag `v0.2` (bad format) → `build` fails at the guard step.
- **First real release** `v0.2.0` (the FlpList breaking change already in `main`) proves the full path.
- `actionlint` + `zizmor` on the workflow: no findings of severity ≥ medium (unpinned actions, `pull_request_target`, excessive permissions, template injection all absent).

## 8. Expected outcomes
- No long-lived PyPI secrets in the repo or org.
- Every file on PyPI for ≥ 0.2.0 shows "Provenance: Verified, GitHub Actions, andreacuneo/flp, release.yml" on its PyPI file page.
- Every dist also has a GitHub attestation, and the files are attached to the GitHub Release.
- A release cannot happen without (a) green CI on the tagged commit, (b) a valid PEP 440 tag, (c) a human approval.

## 9. Verification
```bash
# after a release vX.Y.Z
V=X.Y.Z
gh release download v$V -R andreacuneo/flp -D /tmp/rel
gh attestation verify /tmp/rel/flpit-$V-py3-none-any.whl -R andreacuneo/flp     # GitHub provenance
uvx pypi-attestations verify pypi --repository https://github.com/andreacuneo/flp \
    pypi:flpit-$V-py3-none-any.whl                                               # PEP 740 on PyPI
curl -fsS -H 'Accept: application/vnd.pypi.integrity.v1+json' \
    https://pypi.org/integrity/flpit/$V/flpit-$V-py3-none-any.whl/provenance | jq .
uv run --isolated --no-project --with flpit==$V python -c "import flpit; print(flpit.__version__)"
uvx zizmor .github/workflows/release.yml
```
Manual: PyPI file page shows the provenance panel; the GitHub Release has the dist files attached.

## 11. Risks / open questions
- **Preview action churn**: `astral-sh/attest-action` may introduce breaking changes before 1.0. Mitigation: SHA pin, Dependabot PRs reviewed manually, CLI fallback (§3.3), and the `ls dist/*.publish.attestation` guard so a silent no-op cannot pass.
- **Ordering pitfall**: running the attest step after `uv publish` "succeeds" but uploads no attestations; the guard step plus `verify-pypi` catch this.
- **Re-running a failed publish**: PyPI rejects re-uploads of an existing filename; `uv publish` skips files that are already uploaded and identical (`--check-url https://pypi.org/simple/` can be added to make this explicit).
- If the maintainer is the only reviewer, being on holiday blocks releases (accepted).
