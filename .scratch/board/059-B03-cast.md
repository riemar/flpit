# B03: `cast` (backfill)

## 1. Goal
`cast` exists (runtime `isinstance` check per element) next to `as_type` (zero-cost static re-typing), but the contract between the two is undocumented and `CastTests.cs` is not ported. Reading `linq.py` shows: invalid `target_type` values (`list[int]`, `typing.Any`, `None`, a non-runtime-checkable `Protocol`) are accepted at call time and fail lazily inside the loop with an `isinstance` error; the error message uses `target_type.__name__`, which crashes for `int | None` or tuples; and there is no dedicated exception type. This card fixes those, decides the `None` and generics semantics, and ports the tests.

## 2. Scope
**In:** `cast(target_type)` on `_LinqOps`; new `InvalidCastError(TypeError)` exported from `flpit`; shared eager validator `_require_isinstance_target` (reused by B04); docs contrasting `cast` and `as_type`; port of `CastTests.cs`.
**Out:** numeric conversions (`int` → `float`): .NET `Cast` is a reference/unboxing cast, never a conversion, and so is ours. `as_type` behaviour (unchanged).

## 3. Detailed design
### 3.1 Signatures
```python
@overload
def cast(self, target_type: type[TResult]) -> FlpIt[TResult]: ...
@overload
def cast(self, target_type: types.UnionType | tuple[type[Any] | types.UnionType, ...]) -> FlpIt[Any]: ...
```
.NET `Cast<TResult>(IEnumerable)`: the generic type argument becomes the `target_type` argument. `int?` / `string?` map to `int | None` / `str | None` (overload 2, typed `FlpIt[Any]`; use `.as_type(...)` afterwards for a precise static type until PEP 747 `TypeForm` is usable, see §11).

### 3.2 Semantics
- Kind: intermediate, deferred. Buffering: streaming. Short-circuit: no.
- Check: `isinstance(item, target_type)` per element; a failing element raises `InvalidCastError` **at enumeration**, after all earlier elements were yielded (`ThrowOnUncastableItem`: `cast(int).take(5)` succeeds when element 6 is bad). Message mirrors .NET: `Unable to cast object of type 'str' to type 'int'.` (union/tuple targets rendered with `repr`).
- Validation (eager): `target_type is None` → `ArgumentNoneError("target_type")`. Anything `isinstance` would reject (parameterized generics such as `list[int]`, `typing.Any`, `Literal[...]`, non-`@runtime_checkable` protocols) → `TypeError` **at call time**: "cast() needs a class, a union of classes or a tuple of classes; got list[int]. Use cast(list) for the runtime check and as_type(list[int]) for the static type." Detection: one probe `isinstance(_PROBE, target_type)` inside `try/except TypeError`, which tracks exactly what the running Python version accepts.
- **Generics decision:** reject, do not erase. Checking only the origin (`list`) for `list[int]` would give false confidence about the element type.
- **`None` elements:** `cast(str)` rejects `None` (Python has no implicit nullability; `FlpIt[str]` must not contain `None`). `cast(str | None)` and `cast(int | None)` accept it. .NET `Cast<string>` lets `null` through and `Cast<int>` on `null` throws `NullReferenceException`; here both non-optional forms raise `InvalidCastError`. **README deviation entry.**
- `bool` is an `int` (`cast(int)` accepts `True`); `int` is not a `float` at runtime (`cast(float)` on `1` raises, the same as .NET `Cast<double>` on boxed `int`). Documented.
- `cast` vs `as_type`: `cast` is O(n) checked, returns a new query, raises on bad data; `as_type` is O(1), returns `self`, never checks. Docstrings of both cross-reference each other.

### 3.3 Implementation sketch
```python
def cast(self, target_type):
    _require_isinstance_target(target_type, "target_type")      # eager, shared with of_type
    def _generator():
        for item in self:
            if not isinstance(item, target_type):
                raise InvalidCastError(item, target_type)
            yield item
    return FlpIt(_FactoryIterable(_generator))
```
- O(n) time, O(1) memory. Not `filter`/`map` based: the raise must happen in order, after earlier yields.
- Fast path `target_type is object`: `object` accepts everything including `None`, so return the source wrapped without per-element checks (observationally identical). Any other shortcut (for example "source is a `list[int]`") is impossible at runtime and not attempted.
- **FlpList:** no override.

## 5. Differential harness
`difftest/specs/cast.toml`: object-typed sources mixing `int`, `str`, `null`, `double`; targets `{int: int, string?: str | None, double: float, object: object, int?: int | None}`; probe = index of the first failure and the element count yielded before it. Expected: MATCH except `string` (non-nullable) on `null` elements → `EXPECTED_DIFFERENCE` (reason: deviation in §3.2) and `int` on `null` (`NullReferenceException` vs `InvalidCastError`: classified by exception family "cast failure").

## 6. Benchmarks
`tests/benchmarks/test_bench_cast.py`, sizes 1e3 and 1e5, all elements valid:
- `native`: `def checked(xs, t): for x in xs: if not isinstance(x, t): raise TypeError; yield x` then `list(checked(data, int))`.
- `flpit-FlpIt`, `flpit-FlpList`: `.cast(int).to_list()`; plus `.as_type(int).to_list()` to document the zero-cost alternative.
- Target ≤ 1.5× (measured today ≈ 1.7×: 3.69 ms vs 2.12 ms at 1e5; most of the gap is `to_list`, B09).

## 7. Docs
- Docstring: `.NET: Enumerable.Cast<TResult>()`; per-element `isinstance`, lazy failure, eager target validation; `None` rule; "see also `as_type` (no check) and `of_type` (filter instead of raise)". Doctest: `flp.it([1, None, 2]).cast(int | None).to_list()` → `[1, None, 2]`.
- README "Intentional Semantic Deviations": `None` vs non-optional targets; parameterized generics rejected; `bool` is `int`.
- Translation map: `.Cast<T>()` → `.cast(T)`; `.Cast<T?>()` → `.cast(T | None)`; `typing.cast(list[T], xs)` (static only) → `.as_type(T)`.

## 8. Expected outcomes
- Bad `target_type` fails at the call site with an actionable message; bad data fails with `InvalidCastError` at the element.
- 23 ported .NET tests green; behaviour of `cast` vs `as_type` documented.

## 11. Risks / open questions
- `InvalidCastError` is a new exception not listed in board README §3.1; it subclasses `TypeError`, so existing `pytest.raises(TypeError)` tests stay green.
- Typing of union targets is `FlpIt[Any]` until pyrefly supports PEP 747 `TypeForm`; revisit then (follow-up, no API change).
- The probe `isinstance(_PROBE, target_type)` runs a custom metaclass `__instancecheck__` once at call time; documented, considered harmless.
